  # Fish Ecosystem
    #### Video Demo: https://youtu.be/19NcYuaR3M0?si=E0XLBmqGfibyc_qs
    #### Description:

    This project is a basic model of a fish ecosystem using predator-prey relationships at a small scale. It acts as a mini game to test and see how ecosystems might react using these predator-prey relationships. There are 3 locations to the game, the lake, ocean, and river which all are fundamentally the same ecosystem, they just have different names for the fish and are independent of each other. In a given location, there are 4 fish that interact with each other. They all have expected populations, which is the population at which the ecosystem is healthiest and balanced. These populations are 3, 9, 27, and 81.

    The primary function the user can control is the night function, which simulates the predator-prey relationships talked about before. To simulate the relationship, if a fish has a predator (the fish with a lower expected population above it in the food chain) and prey (the fish with a higher expected population below it in the food chain), the algorithim compares the current population of these fish with their expected values to change the population of the main fish. The main variable that determines the change in population of the main fish I called the pop_value. The pop_value multiplies the current population of the fish by its value and then adds that product to the population.

    Determining how to create the pop_value was the most difficult part of the project. Lets say for example we are in the Lake, and we are evaluating what should happen to the perch population based on its predator (pike) and prey (bluegill). The formula that determimes the pop_value is basically three fractions minus 3. One of the fractions is the expected pike / population of the pike, meaning it will be greater than 1 if there is less pike than expected or less than 1 if it is more than expected. The next is the oppsite with the bluegill, population bluegill / expected bluegill. And the third is the expected population of the perch / population of the perch. The sum of these three fractions are subtracted by 3 to get the pop_value. If these fractions all sum to 3 (are all separately basically = to 1), then the population should stay roughly the same. But if they sum less than three, the population should decrease, and if they are greater than 3, they should increase. This way, the pop_value's sign and magnitude represents the direction and magnitude of the change in population of the perch. A side note to this is that the pop_value is also added to a random number -.1. to .1, just to add some randomness into the population. This total value now multiplies the current population of the perch, and combines that product with the current population.

    All of the other less interesting functions I added after the night function. The health function takes the regression from the expected population of each fish and tells the user how close the populations are to their expected. The fish function just reduces the population of the fish selected by the number the user inputs. The pop and total functions print the populations. The reset function resets the populations to the expected and the location function changes the location of where the player is.

    The most challenging part of this project was determining how the night function could accurately determine the new population of the fish without being to extreme and unbalancing the ecosystem or being to passive and not having any change in the ecosystem. I basically had to invent my own formula which seems elegant and simple now but at a time was very complex so I am very proud of the way I tackled that. Another challenge I faced was expanding the project to new functions. The location function was one of the last things I added and casused me to have to redo almost every part of the project, creating a variable for the active location that had to be initialized and changed everywhere.

    Overall, I learned the benifits of thinking ahead while tackling larger programs. the complexities of creating computational functions that are accurate and balanced, and the difficulties of scaling projects.
